# Fresh Market Databricks bundle standards

These rules come from the DevOps team's Databricks bundle repository layout standard.
Follow them whenever you create or change files in a Declarative Automation Bundle (DAB, formerly called
a Databricks Asset Bundle; treat both names as the same thing).

## Layout
- Code lives in `src/<domain>/`, split by runtime contract:
  - `notebooks/` — job-task entrypoints. Read `dbutils.widgets`, then call into `lib/`. Keep them thin.
  - `pipelines/<pipeline>/transformations/` — Spark Declarative Pipeline tables (`from pyspark import pipelines as dp`).
  - `pipelines/<pipeline>/expectations/` — data quality rules as plain dicts named `<LAYER>_RULES`,
    e.g. `SILVER_DROP_RULES`, `GOLD_FAIL_RULES`.
  - `lib/` — pure, testable Python. No Spark session, widgets, or decorators.
- Bundle YAML lives in `resources/<type>/<domain>/`, mirroring `src/`.
- Unit tests go in `tests/unit/<domain>/...`, mirroring `src/`.

## Naming
- snake_case for folders, files, variables, and resource keys.
- File suffixes: `*.job.yml`, `*.pipeline.yml`, `*.dashboard.yml`, `*.genie_space.yml`, `*.vars.yml`, `_domain.vars.yml`.
- Resource keys and domain variables start with the domain prefix: `so_` (store_ops), `dc_` (data classification),
  `abac_`, `ab_` (agent bricks), `admin_`.
- Job and pipeline `name` is exactly `${bundle.name}_${var.environment}_<resource_key>`.
- Never number jobs or tasks (no `Job_01_`, `Task_01_`). Order goes in `depends_on`, and a domain's run order goes
  in its `orchestrator.job.yml`.

## Variables
- Never hard-code catalogs, schemas, warehouse IDs, or emails. Use `${var.catalog}`,
  `${resources.schemas.<key>.name}`, `${var.warehouse_id}`, `${var.notification_email}`.
- One resource uses it → sibling `<resource>.vars.yml`. Several in a domain → `_domain.vars.yml`.
  Several domains → `resources/variables/common.vars.yml` (DevOps-owned; propose changes in the PR).

## Jobs
- Every job has `tags: {domain: <domain>, cost_center: ${var.cost_center}}`.
- Every job has `email_notifications.on_failure: [${var.notification_email}]`. Never an individual's email.
- Use serverless compute (no `existing_cluster_id`). Classic job clusters must set `policy_id`.
- Jobs read governed tables, not raw landing files.

## Pipelines
- Bronze: `@dp.expect_all(BRONZE_RULES)`. Silver: `@dp.expect_all_or_drop(...)`. Gold: `@dp.expect_all_or_fail(...)`.

## Don't touch
- `databricks.yml`, `resources/variables/`, `.github/`, and `tests/bundle/` are owned by DevOps (CODEOWNERS).
  Don't change targets, `run_as`, or permissions. If a change is needed, say so instead.

## Before you finish
- Run `bundle validate` from the Deployments panel, deploy to the `dev` target, then run the
  `admin_rule_checks` job. Fix anything it flags.
